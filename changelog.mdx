  ## Mexico-issued cards and enrollment retry improvements

  - **Card eligibility:** Mexico-issued cards now pass Prava's issuing-country check. Existing
    issuer restrictions still apply.
  - **Enrollment retries:** If Visa verification fails to initialize before a card is provisioned,
    **Try again** now starts a fresh readiness cycle in the same enrollment session.
  - **Card artwork:** Full-enrollment completion can display the card artwork when it is available.

  These improvements are available in production.

<Update

  rss={{

    description: "Payment results identify the transaction card. Quote integrations must read merchant_res instead of shop_pay."
  }}
>
  ## Payment-result card identity and quote context

  - `GET /v1/sessions/{sessionId}/payment-result` now returns `transactions[].card_id`, the source
    of truth for the card bound to the transaction whether preselected or chosen during collection.
  - Quote-backed results return credential-free transaction summaries and expose merchant checkout
    lifecycle context as `merchant_res`. Non-quote and no-order responses omit the lifecycle field.
  - Quote integrations that previously read `shop_pay` must now read `merchant_res`.
</Update>

<Update
  label="September 6, 2026"
  tags={["New", "API"]}
  rss={{
    title: "Enroll a card and set up its passkey without a payment",
    description: "Merchant full-enrollment sessions collect or reuse a vaulted card and complete passkey setup without creating an order or transaction. Create the session with your secret key, open its hosted URL, and poll for completion."
  }}
>
  ## Enroll a card and set up its passkey without a payment

  Prepare a customer's card for future payments in a dedicated enrollment flow.
  `POST /v1/sessions/enroll-card` now accepts `enrollment_mode: "full_enrollment"`
  and returns a session that the customer completes on Prava's secure surface.

  Start with an existing `vault_ref_id`, or omit it to let the customer enter a card.
  Full enrollment provisions the card and completes its Visa enrollment and passkey setup
  without creating an order or transaction. The existing `provision_only` mode continues
  to return a `card_id` directly for an already-vaulted card.

  Create the session on your backend using your secret API key:

  ```json
  {
    "enrollment_mode": "full_enrollment",
    "user_id": "customer_123",
    "user_email": "customer@example.com",
    "integration_type": "full_checkout"
  }
  ```

  Open the returned `iframe_url` unchanged. Your backend can poll
  `GET /v1/sessions/{sessionId}/status` to distinguish a provisioned card from completed
  enrollment. Accept success when `status` is `completed` and `outcome` is `fully_enrolled`.
  Retryable failures can be retried inside the same session using the selected card.

  [Set up card enrollment →](/api-reference/enroll-card) ·
  [Poll enrollment status →](/api-reference/get-card-enrollment-status)
</Update>

<Update
  label="August 28, 2026"
  tags={["New", "API"]}
  rss={{
    title: "Provision a vaulted card from your backend",
    description: "Merchant secret keys can call the card-enrollment API to provision an already-vaulted customer card and receive its card_id without creating a payment."
  }}
>
  ## Provision a vaulted card from your backend

  Merchant integrations can now call `POST /v1/sessions/enroll-card` with a secret API key
  to provision an already-vaulted customer card. Supply the customer identity, `vault_ref_id`,
  and consent reference; the response returns the resulting `card_id`.

  This server-to-server flow creates no order or transaction. It provisions the card;
  passkey setup and payment authorization are separate steps.

  [Provision a card →](/api-reference/enroll-card)
</Update>

  ## CLI mandate setup uses the agent session API

  `@prava-sdk/cli` 3.2.0 fixes `prava mandate create`: it now sends the agent-session
  request format and displays the returned approval URL. Version 3.1.0 sent the request
  to the merchant-session endpoint and expected a different response field.

  ## Shorter agent approval links and clearer setup recovery

  `@prava-sdk/cli` 2.0.0 updates `prava setup` to register a signed request and print
  a short approval link containing a server-issued link ID. Agent metadata is submitted
  during registration instead of being carried in the approval URL.

  prevents registration. Polling stops when a link expires and tells you to start setup again.
