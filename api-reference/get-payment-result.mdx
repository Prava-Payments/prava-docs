A polling endpoint: after the cardholder completes card entry and passkey approval on Prava's secure surface, poll it to read the outcome and, for non-quote checkouts, the single-use credentials.

`GET /v1/sessions/{sessionId}/payment-result` · Authenticated with your secret key.

## Path parameters

<ParamField path="sessionId" type="string" required>The session id from [Create Session](/api-reference/create-session).</ParamField>

## Notes

- For non-quote checkouts, `token` and `dynamic_cvv` contain the virtual card credentials your agent uses at checkout.
- Read `transactions[].card_id` as the source of truth for the card bound to the transaction, whether it was preselected or chosen on the collection surface.
- For quote-backed checkouts, Prava performs the merchant checkout. Results contain credential-free transaction summaries (`txn_id`, `card_id`, and `status`); they never include token, CVV, expiry, or line-item credentials.
- `merchant_res` contains only `status` and optional `orderId`. Read canonical failure details from the top-level `error`. Keep polling while the top-level status is `pending` or `processing`.
- [Sandbox simulation](/api-reference/testing#simulate-successful-payment-completion) can return effective `completed` and `merchant_res.status: "paid"` while `observed_result.status` is `failed`. Those effective statuses are returned only after Core's sandbox completion succeeds; they do not establish merchant settlement. The simulation request is supplied at session creation and is not echoed as a response-side `sandbox_simulation` object.
- Responses use `Cache-Control: no-store`.
- Prava performs a lazy mandate expiry check on every request — expired mandates are reflected in the status.
- After using non-quote checkout credentials, report the outcome via [Report Status](/api-reference/report-status).

## Error responses

| Status | Code | Cause |
|--------|------|-------|
| 401 | `AUTH_1001` | Invalid API key |
| 401 | `AUTH_1002` | Missing or invalid Authorization header |
| 404 | `NOT_FOUND` | Session not found or doesn't belong to your merchant account |

```python Python
)
```

```javascript JavaScript
const resp = await fetch("https://sandbox.api.prava.space/v1/sessions/sess_123/payment-result", {

  },
});
```
